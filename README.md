# Mac Ambient Jev

macOS 上で講義や会話を録音・読み込みし、ローカル音声処理を中心に文字起こしを生成する Swift ネイティブアプリです。

V1 では、録音、VAD、Qwen3-ASR、話者分離、場面判定、近接度判定をローカルで処理します。外部 API を利用するのは Jev の意味分類だけです。汎用 LLM は V1 に含みません。

## 必要環境

- macOS 15 以降
- Apple Silicon
- Swift 6 系
- 初回モデル取得時のインターネット接続

音声認識モデルは初回利用時に取得され、その後はアプリのモデル保存領域から再利用します。

## ビルドと起動

```bash
bash scripts/build_app.sh
open .build/MacAmbientJev.app
```

または、

```bash
bash scripts/run_app.sh
```

## V1 検証

```bash
bash scripts/verify_v1.sh
```

通常の検証では実ASRモデルを必要とする smoke test は実行しません。

Apple Silicon 実機でモデルを含めて検証するときは、

```bash
RUN_MODEL_TESTS=1 bash scripts/verify_v1.sh
```

を使用します。

## Jev APIキー

アプリの「設定」→「Jev」から API キーを入力します。

APIキーは macOS Keychain に保存します。UserDefaults、JSON、イベントログには保存しません。

Jev を無効化しても、録音・VAD・ASR・話者分離などのローカル処理は継続します。
Jev の優先度分類・場面キュー分類が 429、5xx、通信エラーで失敗した場合、そのバッチの残りの区間は送信せず再試行待ちにします。優先度分類の再試行待ち件数は区間ごとに管理し、再試行成功時に減らします。
場面キューは、その時点以降の音響区間だけを候補の確認に使用します。

## 録音とファイル読み込み

メイン画面のツールバーから、

- 「録音を開始」
- 「音声ファイルを読み込む」

を選択できます。

録音中に ASR が遅延しても、原音声保存と音声認識処理は別状態として扱います。
録音中の一時的な保存遅延は最大 10 秒分（48 kHz・512 フレームの入力単位）をリングに保持します。音声入力が欠落した区間は無音で補い、PTS の欠落や停止時の末尾欠落も保存後の警告に反映します。デバイス切断などによる自動停止でも、保存に成功した音声は文字起こし処理へ送ります。
録音開始前の空き容量を測定できない場合は警告して続行します。必要容量を下回ることが測定できた場合だけ録音開始を拒否し、有効なマイク音声を得られなかった開始失敗のセッションは保存しません。

場面イベントが記録順と異なる時刻で届いても、各発話の場面表示と近接度判定は発話時刻以前の最新の場面転換を使用します。同時刻の転換は記録順で決定します。

## マイク入力音量の自動調整

マイク録音中は、発話検出（VAD）が発話と判定した区間の音量から、macOS のシステム入力音量（「システム設定」→「サウンド」→「入力」の音量スライダー）を少しずつ調整します。設定画面の「マイクの入力音量を自動調整する」で切り替えられ、初期状態はオンです。録音中は切り替えられません。音声データそのものを増幅する処理（デジタルゲイン）は行いません。システム音声モード、音声ファイルの読み込み、保存済み録音の再処理では入力音量に触れません。

- システム入力音量は Mac 全体の設定です。録音中に変更すると、同じマイクを使う他のアプリにもすぐに反映されます。
- 声が小さい状態が続くと 0.05 ずつ（最短 5 秒間隔）上げ、声が大きすぎる場合は 0.05 ずつ下げます。入力がクリップ（音割れ）した場合は 0.10 下げます。
- 録音を停止すると、アプリが変更した音量だけを録音前の値に戻します。録音中にスライダーを手動で動かした場合や既定の入力デバイスが変わった場合は、その録音では自動調整を止め、停止時もその音量を保ちます。自動調整は次の録音まで再開しません。
- 書き込みが完了したか確認できない場合は、手動の値を上書きしないよう元に戻す処理を行いません。入力音量の読み取りと書き込みは他のアプリの操作と不可分ではありません。
- 録音中にアプリを終了した場合、強制終了した場合、クラッシュした場合は元に戻しません。上げた入力音量はそのまま残るので、必要ならサウンド設定で戻してください。
- 入力音量を変更できないマイク、すでに最大のマイク、自動調整がオフの場合でも、声が小さい状態が続くと警告を表示します。音割れが続く場合も警告します。これらの警告は自動調整の設定に関係なく表示し、音量が回復すると消えます。
- 入力音量を変更できない・書き込みに失敗した・元に戻せなかった場合は、理由を添えて赤いエラーとして表示します。元に戻せなかったエラーは次の録音を始めるまで表示されます。
- 発話検出が発話と判定しない音は、どれだけ小さくても音量を上げる根拠にしません。発話検出に失敗した場合は「録音の音量を確認できません」と表示し、音割れへの対応だけを続けます。30秒続く無音の注意は、ミュートや接続の確認用で、この機能とは別です。
- 調整の目的は聞き取りやすい入力レベルに近づけることです。文字起こしの精度向上は保証しません。

参考資料: [kAudioDevicePropertyVolumeScalar](https://developer.apple.com/documentation/coreaudio/kaudiodevicepropertyvolumescalar)（0〜1 のスカラー値。実際の段階はハードウェアに依存します）、[AudioObjectSetPropertyData](https://developer.apple.com/documentation/coreaudio/audioobjectsetpropertydata(_:_:_:_:_:_:))。[AVCaptureAudioChannel.volume](https://developer.apple.com/documentation/avfoundation/avcaptureaudiochannel/volume) は接続ごとのソフトウェアゲインで、システムの入力スライダーではないため使いません。

## システム音声モード

録音ボタンの横で「システム音声」を選ぶと、Mac で再生されている講義や動画をマイクを使わずに文字起こしできます。録音中は入力元を変更できません。初回は macOS のシステム音声録音の許可ダイアログが表示され、応答を待ってから録音が始まります。ダイアログが開いている間は録音も再生確認も始まらず、許可すると録音を開始します。拒否した場合は日本語エラーを表示して開始せず、「システム設定」→「プライバシーとセキュリティ」→「画面収録とシステムオーディオ録音」で許可を有効にしてから再試行してください。再生中の音声は通常どおり聞こえます。再生していない間の無音は正常で、30秒続いた場合だけ注意を表示します。

保存済み録音には「マイク」または「システム音声」の入力元が表示されます。既存の録音は「マイク」として表示されます。グローバルタップは出力デバイスを変更せず、切り替え時も録音を継続します（音声形式が変わった場合は保存して停止します）。実機でシステム音声を確認する場合は、別途 `scripts/verify_system_audio.sh <WAVファイル> <秒数> <セッション保存先>` を実行できます。このスクリプトは指定した WAV を録音開始が確認できてから再生します。権限ダイアログへの応答は時間制限なしで待ちます。拒否すると再生せずエラーを表示します。スクリプトが補助アプリを再ビルド・再署名した後は権限ダイアログが再度表示される場合があります。その場合も許可を確認し、拒否済みならシステム設定で許可を再度有効にしてください。録音と再生を許可できる環境でのみ実行してください。

## データ保存場所

標準実行では、

```text
~/Library/Application Support/mac-ambient-jev/
```

以下にセッション・モデル・設定用データを配置します。

原音声は派生結果より上位の保存対象として扱います。文字起こしや話者分離は再処理可能な派生データです。

## テスト用録音

実講義や個人録音は GitHub に commit せず、

```text
test-data/recordings/local/
```

以下へ置きます。

例:

```text
test-data/recordings/local/lecture-ja-001/
├── audio.m4a
└── segments.json
```

音声ファイルだけを処理する場合:

```bash
swift tools/process-recording.swift \
  test-data/recordings/local/lecture-ja-001/audio.m4a
```

同じディレクトリに `segments.json` が生成されます。

明示的な出力先には入力音声と異なるパスを指定してください（シンボリックリンク経由の同一ファイルも拒否します）。計測用の metrics・thermal・memory 出力先はそれぞれ別のパスにしてください。`--low-heat` はファイル読み込みと中断セッションの確定文字起こしにも適用され、ASR 段階のメモリ計測は `asr` として記録されます。

注釈付きの評価（保持必須語・誤除外・場面転換時刻）は設計から外しました。保持すべき発話が残っているかは、マイクを使った実機試験で確認します。

評価の方針は `docs/evaluation.md`、長時間・障害時の受け入れ試験は `docs/v1-acceptance.md` を参照してください。

## アプリでの動作確認

```bash
bash scripts/build_app.sh
open .build/MacAmbientJev.app
```

Jev を確認する場合は、メイン画面の「設定」ボタンから設定画面を開き、API キーを Keychain に保存して「Jev 接続を確認」を押します。このボタンは固定のテスト文だけを送信し、応答またはエラーを設定画面に表示します。キーを保存していない場合は接続確認を開始できません。実際の録音での Jev 利用状況は設定画面の「診断」で確認できます。

マイクを確認する場合は、設定画面の「マイク録音テスト」で権限を確認します。メイン画面で「録音を開始」を押し、声を入れてから「録音を停止」を押すと、保存状態と文字起こしを確認できます。アプリを開いただけではマイク録音は始まりません。

入力音量の自動調整は、実機のマイクとスライダーでしか確認できません。1 回の録音で 1 つの項目だけを確認してください。Jev への送信を避けたい場合は、先に設定画面で Jev をオフにします。

1. 小さめの声で話し続け、サウンド設定の入力スライダーが数秒おきに少しずつ上がることを確認します。黙っている間は上がらないことも確認します。
2. 自動で上がった後に録音を停止し、スライダーが録音前の位置に戻ることを確認します。
3. 録音中にスライダーを手で動かし、メイン画面に「入力設定が変更されたため、この録音では自動調整を止めています。」と表示され、停止後も手で動かした位置のままであることを確認します。
4. 入力音量を変更できないマイク、またはスライダーを最大にしたマイクで小さめの声で話し、声が小さいという警告が表示されることを確認します。
5. 普通の声でマイクに近づいて話し（叫ばないでください）、音割れした場合にスライダーが下がるか、音割れの警告が表示されることを確認します。
6. 設定で自動調整をオフにして録音し、スライダーが動かないことを確認します。
7. システム音声モードで録音し、入力スライダーが動かないことを確認します。
8. 録音中に表示される日本語の警告が読みやすい位置にあるかを確認し、作成済みの短い録音を再生して音質を確かめます。

音声認識モデルはアプリ内で管理します。初回は設定画面の「音声認識モデル」から先に準備できます。録音開始時、音声ファイルの読み込み時、未完了の文字起こしの再開時にも自動で準備を始めます。初回は約2.5 GBのダウンロードが必要で、準備の進捗はメイン画面と設定画面に表示されます。モデルを準備している間も録音保存と発話検出は続き、準備後に保留中の発話を文字起こしします。次回からはアプリ内のキャッシュを使います。

## V1 の境界

V1 では次を行いません。

- 汎用 LLM の組み込み
- Python worker / Python ASR server
- 常駐 HTTP API
- 常駐 MCP server
- 音声や話者 embedding の Jev 送信

外部エージェント連携は V2 の境界として設計します。
