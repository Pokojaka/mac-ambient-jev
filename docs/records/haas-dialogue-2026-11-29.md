# Haas-ja-v1.0-dialogue を講義録音で試した結果（2026-11-29）

DeNA の会話向け追加学習版 [dena-ai/Haas-ja-v1.0-dialogue](https://huggingface.co/dena-ai/Haas-ja-v1.0-dialogue) を、[段階 1 v2](asr-haas-stage1-v2-2026-11-15.md) と同じ講義 3 本で元の Haas-ja-v1.0 と比べた。

## 判定

講義では大きく悪くなるので採用しない。3 本とも削除が元の 1.7〜2.4 倍に増え、CER は 5〜15 pt 悪くなった。

## 条件

- 会話版のモデル：[tyapa/Haas-ja-v1.0-dialogue-ONNX](https://huggingface.co/tyapa/Haas-ja-v1.0-dialogue-ONNX) commit `9e84cb8adb545a0d229fcc3ed6b4bf34cc4cda9f` の `int8dyn_mm`。
  - Sanami/haas-ja-onnx と同じ変換スクリプトと配置で作られている。tokenizer と `haas_ort.py` は Sanami 版と同じ bytes。各ファイルは同梱の SHA256SUMS で確かめた。
  - 会話版に `int8dyn` はない。このため元のモデルも同じ `int8dyn_mm` で比べ、アプリが使う `int8dyn` は参考に載せる。
- 元のモデル：[Sanami/haas-ja-onnx](https://huggingface.co/Sanami/haas-ja-onnx) commit `354baedfd9612b00e74cc1ae87dff7f2c558db6f`。
- 実行環境：ONNX Runtime の CPU、4 スレッド、Apple M4。
- 入力：段階 1 と同じ VAD 区間。連続する区間を 30 秒以下にまとめる（アプリと同じ）。区間をまとめない場合も測った。
- 参照文：段階 1 v2 の Gemini 4 の参照文。表記は揃えていない（揃える前の CER）。

## CER（表記を揃える前）

30 秒以下にまとめた場合。括弧内は置換 / 削除 / 挿入。

| 録音 | 元 `int8dyn`（参考） | 元 `int8dyn_mm` | 会話版 `int8dyn_mm` |
| --- | ---: | ---: | ---: |
| 組み込みシステム論 | 22.49%（1166 / 960 / 335） | 22.07%（1136 / 946 / 334） | 27.46%（1101 / 1667 / 238） |
| 機械学習入門 | 19.79%（517 / 876 / 168） | 20.45%（526 / 915 / 172） | 34.91%（420 / 2199 / 135） |
| コンピュータネットワーク2 | 18.65%（539 / 690 / 118） | 18.50%（525 / 691 / 120） | 28.86%（421 / 1572 / 91） |

区間をまとめない場合も、会話版は元より悪い（元 `int8dyn_mm` 25.39% / 21.23% / 20.52%、会話版 34.24% / 41.21% / 32.89%）。短い入力の方がさらに悪いので、長い入力で出力が途中で切れることが主な原因ではない。

## 落ちた所

元の出力の半分未満しか出なかった 30 秒以下の chunk を読んだ。

- 教員が学生に話しかける崩れた話し言葉の chunk が、まるごと空になる（コンピュータネットワーク2 で 47 個中 3 個）。
- 数式の読み上げや言い直しを含む chunk では、最初か最後の 1 文だけが残り、残りが落ちる。

モデルカードによれば、会話版は「雑音や聞き取れない背景の話し声には何も返さない」ように学習データの約 1 割を空の参照文にしている。講義の話し言葉の一部も、これに当たって落ちていると考えられる。この原因は推測で、学習データを確かめてはいない。
