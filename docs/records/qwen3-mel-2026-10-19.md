# Qwen3-ASR log-mel 前処理の計測記録（2026-10-19）

[`Qwen3ASRMelFrontend`](../../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/Qwen3ASR/Qwen3ASRMelFrontend.swift) の公式参照実装との照合、Debug / Release の fixture 誤差と同期実行時間、portable test の結果を記録します。これは log-mel 前処理単体の記録であり、ASR 全体の速度や CER を示すものではありません。

## 検証環境と fixture

| 項目 | 値 |
| --- | --- |
| 制御側 host | Apple M4 |

公式 Transformers 4.57.1 の `WhisperFeatureExtractor._np_extract_fbank_features` を明示的に CPU で呼び、各入力を unpadded のまま渡しました。30秒への padding / truncation は行わず、出力値は丸めず全精度で JSON に保存しています。生成手順と pinned 依存集合は [Windows / portable 手順の log-mel 節](../windows.md#qwen3-asr-の-log-mel-前処理)を参照してください。controller が同じ手順を fresh temporary venv で再実行し、全47 version pin で同じ SHA-256 を確認しました。fixture generator を2回実行した determinism check も一致しました。

### 参照実装の処理順序

最後の STFT time frame をどの段階で外すかが実装間で異なります。

| 実装 | time frame 除外と正規化の順序 |
| --- | --- |
| [OpenAI Whisper `audio.py` v20250625](https://github.com/openai/whisper/blob/v20250625/whisper/audio.py) | `stft[..., :-1]` で最後の frame を先に除外し、`abs²` → mel filter → log → 最大値基準の clamp / normalize。 |
| [Transformers 4.57.1 Torch](https://github.com/huggingface/transformers/blob/v4.57.1/src/transformers/models/whisper/feature_extraction_whisper.py) | OpenAI と同様、STFT の最後の frame を `abs²` と mel / log の前に除外し、その後 max / clamp / normalize。 |
| Transformers 4.57.1 NumPy `_np_extract_fbank_features` | T+1 frame 全体で power → mel → log を計算し、**log の後、max / clamp の前**に `[:, :-1]` で最後の frame を除外。その後 max / clamp / normalize。NumPy 経路が log より前に frame を落とすわけではありません。 |
| [Qwen export helper `src/mel.py` (`4aee2ae0c355c7bc33bd5c09befec9e9eabd4b50`)](https://github.com/andrewleech/qwen3-asr-onnx/blob/4aee2ae0c355c7bc33bd5c09befec9e9eabd4b50/src/mel.py) | T+1 frame で mel / log / max / clamp / normalize を行ってから最後の frame を落とすため、上記の公式順序とは異なります。 |
| Swift `Qwen3ASRMelFrontend` | 保持する T frame だけを計算し、その範囲の最大値で clamp / normalize。出力に含めない frame は最大値にも含めず、公式の保持 frame 上の最大値と一致します。 |

### fixture 入力と golden 誤差

従来の5入力の Float32 little-endian 入力 byte string はすべて不変です。追加の `dropped_only_peak` は559 samples、index 558 のみに peak を置きます。保持 frame の window は source index 519 で終わるため、この peak は除外 frame にしか入りません。その出力は559-sample silence の出力（全値 `-1.5`）と完全一致します。一方、既存の `last_frame_peak` は480 samples の index 479 に peak を置き、保持 frame の window にも影響します。従って dropped-only ケースはこの追加ケースだけです。

Debug と Release の最大絶対誤差は同じです。

| fixture | frame 数 | 最大絶対誤差（Debug / Release） |
| --- | ---: | ---: |
| `sine_mix` | 100 | `1.1920928955078125e-7` |
| `chirp` | 23 | `1.1920928955078125e-7` |
| `short_0_3s` | 30 | `1.1920928955078125e-7` |
| `last_frame_peak` | 3 | `1.1920928955078125e-7` |
| `minimum_reflect` | 1 | `5.960464477539063e-8` |
| `dropped_only_peak` | 3 | `0` |

Swift golden test の許容差は `2e-7` です。最大実測誤差 `1.1920928955078125e-7` に対して約1.68倍の余裕があります。

filter の独立照合では、公式 filter と librosa の float64 Slaney mel filter（fmax 8,000 Hz）の最大差は `4.5102810375396984e-16` で、`np.testing.assert_allclose(rtol=1e-12, atol=1e-15)` を満たしました。別途行った OpenAI chirp cross-check の最大差は `3.707408905029297e-5`、この比較専用の guard は `5e-5` です。これは Float32 Torch window / FFT による数値差を含む別の照合であり、Swift と NumPy の `2e-7` 許容差とは別です。bitwise 一致を主張するものではありません。

## Debug / Release 計測

benchmark は同じ sine mix（480,000 Float32 samples、16 kHz mono、30秒。440 Hz / 振幅0.5と1,000 Hz / 振幅0.2）を同期処理しました。opt-in benchmark は既定では skip されます。

| build | 初回（秒） | warm 最小（秒） | warm 中央値（秒） |
| --- | ---: | ---: | ---: |
| Debug | 1.330826875 | 1.133802959 | 1.249815793 |
| Release | 0.025538 | 0.02497175 | 0.025054375 |

初回値は process-cold ではありません。golden test が先に table を初期化しているためです。

Debug / Release とも、選択された test は8 methods、3 suites で、parameterized test 展開後は15 cases（6 golden、1 regression、1 minimum validation、3 nonfinite、1 silence、1 large input、1 limit、1 performance）でした。実行 command は次のとおりです。

```bash
QWEN3_MEL_BENCHMARK=1 swift test --package-path app/MacAmbientJev --filter Qwen3ASRMelFrontend --disable-xctest --no-parallel -j 1
QWEN3_MEL_BENCHMARK=1 swift test --package-path app/MacAmbientJev -c release --filter Qwen3ASRMelFrontend --disable-xctest --no-parallel -j 1
```

Debug 全体は5.291秒、Release 全体は0.185秒でした。
