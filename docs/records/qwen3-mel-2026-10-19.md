# Qwen3-ASR log-mel 前処理の計測記録（2026-10-19）

2026-10-19に、ONNX Runtime を使わない [`Qwen3ASRMelFrontend`](../../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/Qwen3ASR/Qwen3ASRMelFrontend.swift) の同期計算時間と golden fixture との誤差を計測しました。これは log-mel 前処理単体の記録で、ASR 全体の速度や CER を示すものではありません。

## 環境と入力

| 項目 | 値 |
| --- | --- |
| 制御側 host | Apple M4（`sysctl` で確認） |
| 実行環境 | Linux Docker `swift:6.2-noble`、aarch64 |
| Swift | 6.2.4（`swift-6.2.4-RELEASE`） |
| 実行方式 | 単一 thread の同期計算。外部 FFT library、ONNX Runtime、並列処理なし |
| 入力 | 480,000 Float32 mono sample、16 kHz、30秒。振幅0.5の440 Hz toneと振幅0.2の1,000 Hz toneの sine mix を計測外で生成 |

計測コマンドは次のとおりです。

```bash
swift test --package-path app/MacAmbientJev -c release --disable-xctest --filter Qwen3ASRMelFrontend --no-parallel
```

## 計測結果

各条件で初回1回と warm 3回を測定しました。入力から得られる frame 数は `T = 3,000` です。

| build | 初回 (秒) | warm 最小 (秒) | warm 中央値 (秒) |
| --- | ---: | ---: | ---: |
| Release | 0.016724208 | 0.016194375 | 0.016213167 |
| Debug | 0.691937917 | 0.688877417 | 0.705858292 |

初回値は cold start を保証しません。golden test が先に静的 table を初期化するため、この初回値にも初期化済み状態が影響し得ます。

[`Qwen3ASRMelFrontendTests.swift`](../../app/MacAmbientJev/Tests/MacAmbientJevPortableRuntimeTests/Qwen3ASRMelFrontendTests.swift) の各 fixture との最大絶対誤差は次のとおりです。許容差 `1e-4` は、JSON の小数点以下6桁への丸め（最大 `0.5e-6`）と浮動小数点演算の差を含みます。

[`qwen3_mel_golden.json`](../../app/MacAmbientJev/Tests/MacAmbientJevPortableRuntimeTests/Resources/qwen3_mel_golden.json) は Python 3.12、NumPy 2.5.4、librosa 1.0.0 で生成した339,620 byte の fixture で、SHA-256 は `31b772ac0d41afbd81b16bc70ba97653916a29cbc5c45dc8eaf130a1ae436d8b` です。依存版を固定せずに [`generator`](../../scripts/generate_qwen3_mel_fixture.py) を再実行したところ、同じ環境内依存版 NumPy 2.5.4、librosa 1.0.0 が解決され、同一 fixture を得ました。

## テストと runner の状況

- Release の mel test は8 methods（parameterized case 展開後14 cases）が3 suitesで成功し、合計時間は0.122秒でした。
- Linux full suite は714 tests、24 suites が35.546秒で成功し、既存の opt-in benchmark 3件は skip されました。直接実行した Debug full-suite command は次のとおりです。

  ```bash
  swift test --package-path app/MacAmbientJev --disable-xctest --no-parallel -j1
  ```

- [`verify_portable.sh`](../../scripts/verify_portable.sh) の最初の実行は production build 後、SwiftPM の XCTest discovery compile で duplicate `SwiftShims` error になり、clean 後の再実行でも同じ状態が続きました。最終 standard verify では714 tests、24 suites が17.905秒で成功し、script は `Portable Core, Pipeline, and ONNX build/test verification passed` と出力しました。ただし Docker command 自体は container cleanup 中に `/var/lib/desktop-containerd/daemon/io.containerd.metadata.v1.bolt/meta.db: input/output error` が発生して exit code 125 で終了しており、command 成功（exit 0）ではありません。これは validation runner の問題であり、runtime fallback を意味しません。

Windows では実行していません。Windows の性能や CER に関する主張はありません。
