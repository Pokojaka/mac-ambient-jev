# 話者交替時刻での最終文字起こし分割案

## 観測された問題

現行の確定処理は、VAD 区間を ASR に渡してから録音全体の話者分離を行う。VAD は声と無音の境界を検出するが、話者交替そのものは検出しない。実測した A→B→A→B 朗読では、120秒と240秒の交替をそれぞれ約112–126秒、231–245秒の一つの VAD 区間がまたいだ。行を「複数話者」と表示するだけでは、ユーザーが必要とする話者ごとの本文と時刻にならない。

音源の切り出し点には無音を追加していないが、波形上は120秒直後に約0.42秒、240秒直後に約1.00秒の低音量部分が存在した。後者が VAD で閉じなかった理由は未確定。VAD の最短無音設定は0.75秒である。明示的なデジタル無音1.5秒を挿入した対照音声では VAD が交替前後を分離した。この結果だけで VAD の閾値を変更しない。

## 処理順

1. 保存した処理タイムラインから VAD 区間を取得・検証する。
2. 同じタイムラインを話者分離入力の音声ファイルへ書き出し、オフライン話者分離を**一回だけ**実行して元の `SpeakerSpan` と時刻を得る。モデル内部のリサンプリングは許容し、タイムラインとチェックポイントのサンプルレート・チャンネル数は変えない。
3. 話者 span による有効な交替時刻で VAD 区間を子区間に分ける。子区間は、元 VAD 区間を欠落・重複なく覆う。子区間ごとに決定的な segment ID を付け、イベントログには子区間を `segment.created` として保存する。
4. 子区間ごとに Qwen3-ASR (`language: "ja"`) を実行する。話者ごとに本文を後から文字数で割り振る方法は使わない。ASR が空白や認識失敗の定型文を返した区間は表示・Jev の対象から除くが、処理上のイベントと話者 span は保持する。
5. 話者 span は既存の `DiarizationCoordinator` で推論直後に一度だけ保存し、ASR 後に同じイベントを materializer に渡す。再推論・重複保存はしない。その後の場面・音響範囲・Jev 判定は子区間の本文を使う。新しい active runs は全必須段階の成功後だけ選択し、失敗時には以前の確定結果を維持する。
6. 録音中は閉じた VAD 区間のライブ本文を表示し、録音停止後の確定処理で話者境界に分かれた行へ置き換える。ライブ中の話者 ID 確定はこの変更の範囲外で、画面には確定前後の状態を誤認させない。

## 境界の採用

- 時間順に隣接する異なる話者の span が、同じ VAD 区間内で切り替わる場合だけ候補とする。同一話者の断片間では分割しない。
- 非重複で接する場合は接点、間にギャップがある場合はその中点を切断時刻とする。どちらの側も元の音声を含むため、ギャップの音声サンプルを捨てない。
- 異なる話者の span が時間的に重なる部分では一意の交替時刻を決められないので、そこでは切らず、元 span と「複数話者」の表示を保持する。推測の境界で片方の音声を削らない。
- 話者分離によるごく短い別話者 span は誤判定の可能性がある。採用する交替の両側には少なくとも0.3秒の当該話者の span を要求する。切断で生じる ASR 子区間も各0.3秒以上とし、条件を満たさない候補は切らずに詳細 span を残す。この数値は実音声で再評価し、黙って短区間を破棄しない。
- 判定は単純な `sortedSpans` の隣接ペアではなく、候補時刻の直前と直後を実際に覆う話者集合で行う。入れ子や重複 span がある候補では一意の左右話者と見なさない。採用・棄却した候補の時刻と理由をテスト結果へ記録する。
- 境界が VAD 範囲外にある場合は使わない。同一フレームや逆順、ゼロ長、重複 ID を作らず、不整合は明示的に失敗させる。

## 保存・復旧

元の VAD 区間は segmentation 入力としてメモリ上に残し、イベントログには ASR 入力となる子区間を記録する。segmentation run の完了件数は子区間数と一致させる。各子区間は既存の `PipelineCoordinator`、`ASRAudioLoader`、`SessionRecoveryScanner` が扱える `SegmentReference` とする。話者分離の元 span は録音全体の時刻で一度だけ保存する。途中失敗した新しい run は選択しない。保存済みセッションで再試行する際は現行の finalization 契約どおり**新しい run ID で全体をやり直し**、その run 内の子区間 ID を決定的に生成する。失敗した旧 run の pending イベントは新 run に混ぜない。

`segment.created` を全子区間について保存してから `processing.run.completed(segmentation)` を保存する。保存後に読み戻し、子区間の件数・範囲・ID と完了件数が一致することを確認する。`NativeSessionProcessor` の finalization メタデータが active runs の組を全段階成功後にまとめて選択する現行契約は維持する。途中失敗の新 run はログに残っても、選択済みの旧 run と混在させない。

## 検証

- 単体テスト: 1 VAD 区間内の A→B を2子区間・2 ASR 呼び出しにする。同一話者断片・短い揺れ・重複発声・範囲外 span は不要な分割をしない。子区間が元区間を欠落・重複なく覆い、イベントと復旧対象の ID が一致する。
- ギャップあり A→B の中点、接触点、入れ子・重複 span、0.05秒の別話者揺れ、0.3秒ちょうどの相づちを固定し、子区間のフレーム総和が親と一致することを検証する。ASR への実サンプル範囲も半開区間の境界で欠落・重複しないことを確認する。
- 実音声: 既存の A→B→A→B 音声で既知の120・240・360秒前後の最終行が別々の話者になるか、`S1→S2→S1→S2` に戻るかを確認する。音声の継ぎ目に元からある低音量部分と、明示的な無音を入れた対照音声を別々に評価する。
- 変更前の同音源で得た具体的な span は、120秒で S1 終端120.203秒・S2 開始120.373秒、240秒で S2 終端240.169秒・S1 開始241.069秒、360秒で S1 終端と S2 開始が360.016秒。中点規則なら前二者は約120.288秒・240.619秒に切れる。これらは既存モデルの推定 span であり、音声を聴いて付けた正解境界ではない。既知の接続時刻との差も併記する。
- ファイルと原速ライブ経路: 同じ音声でチェックポイントのサンプル数を先に比較し、停止後の子区間・本文・話者を比較する。ライブ遅延は既存ハーネスの発話終了から非空更新までで測る。最終分割は停止後の結果として別に記録する。
- 分割前後で同じ音声の本文差分、空本文・定型文の発生、ASR 呼び出し回数と総処理時間を比較する。短い子区間も計時から除外せず、分割で確定処理がどれだけ遅くなるか記録する。
- `swift test`、`scripts/verify_v1.sh`、`.app` と zip の再作成を最後に実行する。青空朗読などの第三者音声は配布しない。

## レビューで特に確認したい点

1. 0.3秒の話者持続・子区間長の下限は妥当か。短い相づちを欠落させないか。
2. ギャップ中点と重複時の非分割は、話者別本文と音声欠落防止の両立として妥当か。
3. 話者分離を ASR 前に動かすとき、イベントログ・active runs・保存済みセッション復旧に破綻がないか。
4. 区間分割による ASR 品質・速度の悪化を、どのテストと失敗条件で検出するか。

## Nemotron 3 Diarization の調査と採用条件

NVIDIA の [モデルカード](https://huggingface.co/nvidia/Nemotron-3-Diarization)と [Transformers の実装資料](https://huggingface.co/docs/transformers/main/model_doc/nemotron3_diarization)によると、Nemotron 3 Diarization は最大8話者のフレーム単位の話者確率を10ms刻みで出力し、オフラインと逐次処理に対応する。逐次処理の最短推奨入力待ちは0.32秒であり、推論・ASR・表示を含む実測遅延ではない。重複発声の出力にも対応する。モデル内部は16kHzモノラルを使う。一方、[NeMo-Speech.cpp の C ABI](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/sdk.md)はモノラル float32 の8–96kHz入力を受けて内部でリサンプリングする。いずれの経路でも録音・ファイルの元形式とチェックポイントを変更せず、必要なダウンミックスだけを推論境界で行う。

[MLX Community 版](https://huggingface.co/mlx-community/Nemotron-3-Diarization)は Apple Silicon 上で `mlx-audio` の Python API によるオフライン処理と PCM chunk 投入を提供する。さらに NVIDIA 公式の [NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp) の現行ソースは Nemotron 3 話者分離をサポートし、[macOS/Metal の `metal-diar` ビルド](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/build.md)と [C ABI](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/sdk.md)を提供する。ただし公開済み v0.1.0 バイナリの説明は旧 Sortformer v2 までなので、Nemotron 3 での利用には現行ソースからのビルドが必要になる可能性がある。Swift アプリからネイティブ連携する経路はあるが、この端末でのビルド・推論・配布物組込みは未検証。この設計の初回実装では既存の話者分離エンジンを使い、境界分割とイベント整合性を先に完成させる。Nemotron 3 を採用するには C ABI アダプター、モデルの配布・容量、入力変換、失敗復旧を別途実装・検証する必要がある。

両エンジンに同じ A→B→A→B 評価音声を通し、**音源の接続時刻として既知の**120・240・360秒に対する境界誤差、余計な交替、A に戻る ID 安定性、処理時間、ピークメモリを記録する。この音源には声の重なりがないため、重複発声の精度評価には使わない。

自然な朗読については、[青空朗読の『よだかの星』掲載ページ](https://aozoraroudoku.jp/voice/rdp/rd001.html)に二人の読み手が記載されていることを確認し、[青空文庫の原文](https://www.aozora.gr.jp/cards/000081/files/473_42318.html)と全編 ASR の本文を順序付きで照合する。原文中の台詞・段落などの文字列を時刻へ対応付け、話者分離 span と声の特徴が安定して切り替わる箇所を**交替候補**として抽出する。各候補には根拠となる前後の本文、時刻、両モデルの span、信頼度を保存する。原文中の登場人物交替が読み手交替と同じとは仮定せず、同じモデルの出力を正解ラベルに流用しない。聴取で確定していない候補は境界誤差の正解付き採点から分け、候補の一致・不一致として報告する。既知の人工的な接続点だけで自然な朗読の優劣を決めない。モデルカードの DER は本アプリの日本語朗読精度を保証しない。

## OpenCode レビューの反映

MiMo V2.6 Pro と Qwen 3.8 Max にこの設計と `FinalTranscriptPipeline`、`DiarizationCoordinator`、`PipelineCoordinator` を送り、両者からレビューを得た。両者が確認した部分実装の欠陥は、接触した span しか切れずギャップをまたぐ交替を逃すこと、0.3秒の話者持続ではなく ASR の最短入力長だけを使うこと、子区間の `segment.created` より前に親区間数で segmentation 完了を書くこと。これらを実装修正の必須条件とする。子 ID は親区間ごとの番号か開始フレームから作り、前の親区間の分割数に依存させない。

両レビューの提案のうち、推定境界近傍の低音量点探索は今後の実測対象とし、まず中点・接触点で無音を捨てない処理を完成させる。再試行時の旧 run 再利用や追加イベントの提案は採用しない。現行の `completeFinalization` は全段階成功後に active runs 一式を選択し、失敗時には以前の組を保持するため、新 run で全体再試行する契約と整合する。`NativeQwen3ASREngine` は既に `language: "ja"` を渡し、materializer と Jev は空本文・定型文を除外している。確定処理の `PipelineCoordinator` は通常ペーシングなので、レビューが懸念した `lowHeat` の子区間数比例の待機はこの経路では起きない。
