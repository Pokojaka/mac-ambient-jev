# V1 完了検証の実行計画

この計画は [`2026-09-22-clean-transcription-core-v1.md`](2026-09-22-clean-transcription-core-v1.md) の Task 10〜12 と最終確認、[`設計書`](../specs/2026-09-22-clean-transcription-core-design.md) の性能指標、[`受け入れ試験`](../../v1-acceptance.md) を実行するためのもの。引き継ぎ文書は既知の実行結果と制約の記録として使う。

CLI の復旧経路、計測値の定義、14秒分割後の極短端数の扱いは [`V1 完了検証の実装設計`](../specs/2026-09-24-v1-completion-execution-design.md) に記す。ユーザーの指定により、注釈付き golden corpus の作成と誤除外指標の合否判定は今回の範囲から外す。元の実装計画書と設計書に含まれる条件だったことは記録し、合格済みと扱わない。

## 完了条件

今回の完了条件は、ビルド・通常テスト・実モデル smoke の成功、録音ファイルの import から ASR・話者分離・場面判定・範囲整理までの完了、60〜90分録音の性能記録、録音と処理の独立性、未完了 ASR の復旧とする。注釈付き corpus の用語保持率・誤低優先度・誤背景は今回判定しない。原設計に対する V1 全体の合格判定には、さらにライブ録音、録音中の強制終了からの復旧、マイク権限、Jev のキー設定後の接続と切断・再試行の実機確認が必要。指標が `null` の項目や実施していない項目を合格として数えない。

今回もマイクを使わない。ライブ録音、capture dropout、録音中の ASR stall、マイク権限、録音中の強制終了と復旧損失窓は NOT VERIFIED とする。ファイル import 復旧や fake ASR テストで代用しない。Jev の実通信はアプリで API キーが設定された場合に限る。これらが満たせない間は、他の試験が通っても V1 全体を NOT VERIFIED と判定する。

## 現在地と測定の境界

- 2026-09-24 の `test-data/recordings/local/_smoke/verify-2026-09-24-low-heat.log` では Core 109件、Runtime 13件、実モデル smoke、アプリビルドが成功した。実録音処理は4ミリ秒区間で MLX 異常終了した。直前に強制休止を試したため、その影響との切り分けは未完了。新規区間の抑制と保存済み区間の入力境界処理を追加したが、修正後の実モデル復旧は未確認。
- 約73.6分録音は全処理が完了した。約87.6分録音は382区間の ASR 完了後に異常終了し、約84分録音は未処理。15〜33分の討論抜粋は音声を切り出したが未処理。
- 既存の長時間測定は処理時間と最大メモリの比較対象になるが、温度や熱状態の連続記録はない。温度改善の比較値を捏造しない。
- ローカルの音声、セッション、出力、計測ログは `test-data/recordings/local/` とアプリのセッション保存先にのみ置く。Git に追加しない。判断記録は `test-data/recordings/local/_v1-run/decisions.tsv` に追記する。

## Phase 1. 計測経路を先に固める

1. 低発熱モードの差分を設計書の性能モデルに照らして点検する。これは長時間ファイル入力の検証用で、ライブ ASR に固定の待機を加えない。完了イベントを書いた後、次の区間に進む前だけ休むことを fake ASR テストで確認する。モデルを読み込まない既存テストを対照に、欠けている計測は短時間の実モデル処理より前に追加して再テストする。
2. 短い音声で通常実行と低発熱実行を比べる。終了コード、文字起こし結果、処理時間、ASR の待機回数と待機時間を記録する。文字起こしは正規化後の本文を比較し、非決定的な差が出た場合は差分を残して INCONCLUSIVE とする。総所要時間と推論時間を区別し、休止込みの処理時間を ASR 推論 RTF と取り違えない。
3. 長時間試験の記録方法を固定する。各 run は corpus ID と開始日時で命名し、使用した commit SHA、`git diff` のハッシュ、コマンド、環境、出力先を `run.json` に記録する。`Package.resolved` の採用状態も固定する。CLI の `--metrics-output` で得る ASR 計測と `/usr/bin/time -l` の最大 RSS・peak memory footprint を run ID で統合する。自身の footprint を5秒ごとに `memory.jsonl` へ記録し、モデル読み込み時間、ASR queue depth、段階ごとの所要時間、最古 pending age、録音時間と結び付ける。CLI のメトリクスファイルが欠ける場合は計測 run を失敗とし、測れない個別項目は `null` と理由を記録する。
4. `ProcessInfo.thermalState` を長時間 run 中に周期的に記録し、`critical` に達した場合は次の安全な区間境界で run を停止してセッションを保持する方法を確認する。新規 run は熱状態が `nominal` または `fair` に戻ってから始める。空き容量とメモリを確認し、モデル処理・ビルド・別の録音処理を並列に実行しない。

判定ゲートは、短い実モデル入力で低発熱モードが最後まで完了し、通常実行との差分・休止時間・熱状態を記録でき、`engine-metrics.json` から `run.json` へ ASR 計測を渡せること。失敗した場合は長時間録音へ進まず原因を直す。結果は run ID のログと判定行を `decisions.tsv` に残す。

## Phase 2. 自動検証と討論抜粋の処理

1. `RUN_MODEL_TESTS=1 ASR_SMOKE_AUDIO="$PWD/test-data/recordings/local/_smoke/audio.wav" bash scripts/verify_v1.sh` を実行する。通常テスト、実 Qwen3-ASR、リリースアプリ、MLX リソース同梱の結果を保存する。SwiftPM キャッシュの権限エラーならキャッシュ先を一時領域に切り替えて再実行する。
2. 情報セキュリティ基礎の15〜33分抜粋を処理し、`segments.json`、場面イベント、処理時間、最大メモリを残す。失敗時は保存済みセッションからの復旧可否を確認してから再実行する。この処理を golden corpus の精度評価とは呼ばない。

判定ゲートは、スクリプトの終了コード0、実モデルテストの実行記録、討論抜粋の全処理完了と保存結果。用語保持・誤除外の合否は今回判定せず、合格扱いしない。

## Phase 3. 実クラッシュからの復旧

1. 保存済みの約87.6分セッション全体を別のローカル領域に複製し、複製前後の `events.jsonl` のハッシュと完了イベント数を保存する。`--inspect-session` が指定 ID 以外を読まず、対象のイベントログも変更しないことを確認する。`seg_000383` の4ミリ秒が14秒区間の分割後の端数と整合し、382区間が完了済みであることをイベントと `SegmentationAssembler` の動作で確認する。
2. 復旧入口にも低発熱モードを渡し、短い fake ASR fixture で pending だけを再投入する経路を検証する。resume でも対象 ID 以外を走査・修復しないこと、復旧計画の区間 ID 一覧と完了済み ID 一覧に重複がないことを確かめる。新しいセッションへの全量再 import で復旧成功を代用しない。
3. 実モデルで保存済みセッションを復旧し、分割後の4ミリ秒端数を Qwen3 に渡さずに処理できること、完了済み ASR が重複しないこと、active run の切り替えが安全なこと、後段の話者分離・場面・範囲整理が完了することを実データとイベントログで確認する。383の完了イベントは残し、最終 `segments.json` には383を独立区間として出さない。

判定ゲートは、復旧前後の `events.jsonl` の区間 ID 集合で未処理0、重複した完了イベント0、元の録音を保持したまま後段まで到達すること。ファイル復旧は録音中の強制終了試験とは別の結果として記録する。失敗時はセッションを保持し、原因を記録してから再試行する。

## Phase 4. 残りの長時間録音

約84分の録音を低発熱モードで処理する。復旧が完了していなければ約87.6分の全量再処理はしない。モデルを使う処理を同時に走らせず、各 run の終了コードと出力が確定してから次へ進む。

録音時間、実時間、推論時間を分けた ASR RTF、最大 RSS、peak memory footprint、5秒ごとの footprint、最大 queue depth、最古 pending age、周期的な熱状態、モデル読み込み時間、話者分離完了時刻、場面振動件数、失敗と復旧範囲を記録する。ASR RTF は各起動で処理した音声長を分母にし、復旧 run の値を録音全体の値と呼ばない。低発熱モードの休止時間も別欄とし、従来 run との時間差を隠さない。capture dropout、Jev の成功・失敗・再試行件数、録音中の復旧損失窓は測れなければ `null` と理由を記す。ディスク残量または熱状態の開始条件を満たさなければ新規 run を始めない。

判定ゲートは終了コード0、`segments.json` の生成、ASR 以降の全段階の完了、および測定可能な指標の実値と測定不可の理由が `run.json` に揃うこと。`memory.jsonl` が5秒周期の必要サンプル数を満たす場合は、実装設計の512 MiB増加・12 GiB peak の条件で長時間ファイル処理のメモリを判定する。サンプル不足は INCONCLUSIVE、閾値超過は失敗と記す。途中失敗は新規全量処理より先に保存済みセッションの復旧可否を調べる。

## Phase 5. 受け入れ判定と引き渡し

fake ASR の停止中に原音声保存が進む試験、イベントログ末尾破損、pending ASR の再投入、失敗 run が active run を置き換えない試験、Jev が使えない場合のローカル処理試験を、該当する自動テストと生成物で確認する。Jev のキーがアプリに設定された場合に限り少量の実通信、切断中のローカル処理、再接続後の保留分再試行を実機確認する。マイクを使わない間は、capture dropout、録音 callback、録音中 process kill、マイク権限と実録音の遅延・復旧窓を NOT VERIFIED とする。

`docs/v1-acceptance-results-2026-09-23.md` と `docs/v1-acceptance.md` に、実測値・失敗・未検証理由を反映する。最後に全自動検証、`git diff --check`、Git の追跡対象を確認する。判定は各項目を VERIFIED、NOT VERIFIED、INCONCLUSIVE のいずれかで記す。マイク実機試験と Jev 実通信が未検証の今回、V1 全体の判定は NOT VERIFIED のままとする。後日の全条件が VERIFIED になった場合だけ合格を記す。

## 実行順と作業の分離

最初に計測と短い再現を通し、討論抜粋、既存セッション復旧、残りの長時間録音の順に進む。モデル処理は1件ずつ実行する。コード担当は独立した worktree を使い、共有ビルドと実録音の処理は親作業ツリーで直列に行う。各段階のゲートの成否と証拠を `decisions.tsv` に1行ずつ記し、失敗時は次へ進まず仮説・修正・再測定を追加で記録する。
