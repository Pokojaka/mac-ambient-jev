# 書き出しと保存済み録音

## 文字起こしの行集合

画面と `transcript.txt` は `LiveTranscriptProjection` が選んだ同じ発話を使う。次の発話は表示・テキスト書き出しから除く。

- 本文が空、または空白だけの発話。
- 場面が `discussion` で、音響範囲の span があり、そのすべてが `background` の発話。

低優先度の発話は画面では折り畳むが、書き出しには原文を含める。テキストには低優先度の印を付けない。「聞き取れませんでした」などの文字列だけで発話を除外しない。認識不能は ASR の構造化状態 `outcome: empty` で扱う。イベントには空本文を含む区間が残る。

`segments.json` は空本文を除いた公開 JSON であり、背景のみの発話も含む。画面・テキストと JSON の行集合はこの点で異なる。[保存形式](storage.md)を参照。

## transcript.txt

`TranscriptTextRenderer` が開始時刻と話者見出しを付け、UTF-8 で 1 行 1 発話を書き出す。各行末は改行。

```text
[00:07] Speaker 1: 本文
[12:34] Speaker 1 / Speaker 2: 本文
[65:00] UNKNOWN: 本文
```

時刻は開始ミリ秒を秒へ切り捨てた総分数と秒数。1 時間を超えても分数を使う。話者番号は `Speaker 1`〜`Speaker 7`、それ以外は `OTHER`、割り当てがない場合は `UNKNOWN`。

話者と重なる時間の合計に対して 1 人が 80% 以上ならその話者だけを見出しにする。80% 未満なら出現順に ` / ` で併記する。本文内の CRLF、LF、CR、U+2028、U+2029 は空白へ置換する。話者分離前の発話には見出しがなく、テキスト書き出しは「話者分離されていない発話（区間 ID）があるため書き出せません」で失敗する。[確定処理](final.md)を参照。

## 音声とフォルダー名

録音は保存済みの `recording.flac`（16 kHz・mono・16-bit FLAC）を全フレーム復号して検証したうえで、`audio.flac` に無変換でコピーする。0.256 秒（4,096 フレーム）未満の録音は保存時に末尾を無音で埋めてあるため、`audio.flac` は末尾に無音が付いて 0.256 秒になる。保存状態が FLAC でない録音は「録音の FLAC 化が終わっていないため書き出せません。確定処理をやり直してください」で失敗し、その場で符号化はしない。起動時の保存整理中（`isMaintainingStorage`）に、まだ `recordingPCM` の録音を書き出そうとした場合は、アプリが書き出しの前に止め、「保存済み録音の音声を整理しています。整理が終わってから書き出してください」と表示する。読み込み音声は保存済み original を再圧縮せず複製し、ファイル名は `audio` と元の拡張子を結合する。音声の選択はセッションの種類で決まり、派生 timeline の有無では切り替えない。書き出しはセッション内の音声を読むだけで、`recording.flac`、original、`storage.json` のいずれも削除・変更しない。保存状態は書き出しの開始時に `storage.json` から決める。

書き出しフォルダー名は保存済みセッションの実フォルダー名をそのまま使う。作成時に固定したタイムゾーンで決めた名前を再計算しないため、現在のタイムゾーンや書き出し時刻で変化しない。

作成時の形式は次のとおり。

```text
YYYY-MM-DD_HH-mm-ss_<stem>_<8 lowercase hex>
```

録音例: `2023-11-14_22-13-20_録音_0123abcd`。読み込み例: `2023-11-14_22-13-20_定例会議_0123abcd`。時刻はセッション作成時に指定したタイムゾーンで一度だけ決まり、読み込みでは読み込み時刻、録音では録音開始時刻を使う。stem の sanitization、切り詰め、検証は[保存形式](storage.md)を参照。

設定の「保存先」で書き出し先を選ぶ。書き出しは Application Support 内のセッションを移動しない。同じセッションの再書き出しは同名のフォルダーを置き換える。まず非表示の作業用フォルダーでテキストと音声を揃えてから公開する。失敗時は作業用フォルダーを削除し、削除にも失敗した場合は元の書き出しエラーと削除エラーを併記する。

## 自動書き出しと保存先

「処理完了後に自動で書き出す」の初期値はオン。保存先が設定され、公開済み文字起こしがあり、処理状態が完了または意味分類の再試行待ちなら自動書き出しする。未処理・処理中・一時停止・失敗・破損の状態では自動書き出ししない。

保存先は security-scoped bookmark とパスを `UserDefaults` に保存する。参照できない保存先は選び直しを求め、別フォルダーへ切り替えない。自動書き出し設定の型が不正なら「自動書き出しの設定を読めないため、自動では書き出しません。設定の「保存先」で切り替え直してください」と通知して書き出しを止める。

書き出し中は進捗を表示し、同じセッションの重複書き出しを防ぐ。書き出し済みの判定は対象フォルダーに `transcript.txt` とそのセッションの音声ファイルが両方存在すること。書き出し済みのセッションには「書き出し先を Finder で表示」が出て、書き出したフォルダーを開ける。保存済み録音の詳細には、書き出しの有無にかかわらず読める録音と読めない録音の両方で「録音データを Finder で表示」が出て、アプリ内に保存しているそのセッションのフォルダー（カタログが持つ実際の URL）を選択して Finder で開く。設定の「保存先」にある「録音データ」の「Finderで表示」は、全セッションを入れた sessions フォルダーを開く。フォルダーが存在しなければ作らずにエラーを表示する。

## アプリのウィンドウ

Dock と Finder のアプリアイコンは、暗い角丸タイルに白い紙のしおりと橙色の波形・文字の行を組み合わせたデザイン。元画像は `app/MacAmbientJev/Assets/AppIcon.png`。16・32・128・256・512 pt の標準解像度と Retina 用の画像を収めた AppIcon.icns を app bundle の Contents 内の Resources フォルダーに置き、`Info.plist` の CFBundleIconFile で指定する。

メインウィンドウ「MacAmbientJev」は単一インスタンスとし、同時に複数は開かない。File メニューの New Window とそのショートカット Command-N は提供しない。

メインウィンドウは起動時に開く。SwiftUI の主シーンに `Window` を使うため、メインウィンドウを閉じるとアプリは終了し、Dock アイコンをクリックすると再起動してメインウィンドウを開く。`defaultLaunchBehavior(.presented)` により、復元するウィンドウがない起動時と、実行中のアプリに可視ウィンドウがない状態での Dock クリック時にもメインウィンドウを表示する。

## 保存済み録音の一覧

保存済み録音はメイン画面のボタンで開く独立したウィンドウ「保存済み録音」に表示する。通常のウィンドウなので閉じるボタンと Command-W で閉じられ、開いたままでもアプリを終了できる。

一覧は作成日時の新しい順。セッション情報を読めない項目は読める項目の後ろに置き、理由を表示する。入力元は「マイク」「システム音声」「読み込み音声」で区別する。

| 状態 | 表示 |
| --- | --- |
| 未確定・公開済み結果なし | 未処理 |
| 確定処理の実行中 | 処理中 |
| 熱による一時停止 | 一時停止中（発熱） |
| 完了・公開済み文字起こしあり | 文字起こしあり |
| 完了・公開済み文字起こしなし | 処理完了 |
| 完了・Jev 保留あり | 文字起こしあり・意味分類を再試行 |
| 確定処理失敗 | 再処理が必要: 理由 |
| processing_metadata.json の読み取り失敗 | 文字起こしデータが破損しています（音声から再処理できます） |

音声がない場合は「保存済み音声がありません」、音声を読めない場合は「音声を読めません: 理由」を処理状態より優先して表示する。セッション情報の欠損・破損、フォルダー名と manifest の不整合、完全セッション ID の重複は項目全体を読み込みエラーとする。行の identity と選択は実フォルダー URL を使い、UUID を読めないフォルダーも個別に選べる。

再処理には読めるセッション情報と利用できる原音声が必要。派生 metadata の破損だけなら原音声から再処理できるが、破損状態の書き出しは許可しない。書き出しにはさらに公開済み文字起こしが必要。録音中は保存済み録音の選択を無効にし、録音・読み込み中や同じセッションの処理待ち・処理中は再処理を重ねて開始しない。

一覧は active ASR run のイベントログと active transcript payload を読み取り専用で検証する。ログが欠損・不正、または不完全な末尾を含む場合は破損状態となり、文字起こしを公開せず書き出しを無効にする。再処理は利用可能な原音声から行える。
