# アーキテクチャ

Mac Ambient Jev は、保存音声を基にローカルで文字起こしを作る Swift アプリです。音声保存と推論を分離し、認識・話者分離・BTSJ 発話文の境界・優先度の結果をイベントとして保持します。画面や書き出しは、公開済み run のイベントから組み立てます。保存形式の詳細は [storage.md](storage.md) を参照してください。

## パッケージとモジュール

定義の正本は [Package.swift](../app/MacAmbientJev/Package.swift) です。Swift tools version は 6.0、macOS の最低バージョンは 15 です。

ONNX target は汎用 ONNX 推論 API と SileroVAD の frame probability API を提供します。公開 `SileroVAD.frameSamples` は512で、SileroVAD は16 kHz mono の512-sample frameごとに確率を返します。ONNX opset 15 export は、Mac Runtime が使う FluidAudio 0.15.8 の Core ML artifact `silero-vad-unified-256ms-v6.2.1` と同じ v6.2.1 Silero VAD model weights を使います。Mac Runtime はこの artifact で16 kHz の連続 recurrent state で512-sample frameを8個処理します。Mac と ONNX の segmentation layer contract は、8 frameの probability `p_i` を noisy-OR `1 − Π(1 − p_i)` で256 msごとに1つへ集約し、threshold 0.50 を適用し、最後の部分 chunk を最後の sample の反復で埋めることです。`SileroVAD` は frame probability のみを返し、8 frame の集約、発話の開始・終了判定、区間作成は Pipeline の VAD 規則と PortableRuntime の Silero engine が行います（[windows.md](windows.md#silero-vad-の区間検出)）。呼び出し側がプロセススコープで共有する `ONNXEnvironment` を1つ作成し、各 `ONNXSession` はそれを保持します。`ONNXTensor`（コピーあり）と `ONNXValue`（コピーなし）による名前付き複数入出力は float32 / int64 を扱い、intra-op thread 数は session ごとに指定します。実行は CPU provider のみです。SileroVAD の model、frame contract、test fixture は [windows.md](windows.md#silero-vad-フレーム推論)、固定版 SDK の取得・hash 検証、link、テスト時の Windows DLL 配置は [windows.md](windows.md#onnx-runtime) と [windows.md](windows.md#ビルドと検証) を参照してください。

## Portable Core の境界

Core、Pipeline、EngineProtocol、EngineHost、Diarization は Apple 専用 framework adapter を持たず、EngineProtocol と Diarization は Foundation のみを使います。[scripts/check_portable_core.py](../scripts/check_portable_core.py) は Core / Pipeline / EngineProtocol / EngineHost / Diarization / ONNX / PortableRuntime の Swift ファイルを走査し、AVFoundation、AppKit、CoreAudio、CoreML、Security、SwiftUI、AudioToolbox、CryptoKit、IOKit、CoreMedia、Combine、ScreenCaptureKit、FluidAudio、MLX / Qwen3ASR、AppleSupport、Runtime、Capture などの import を禁止します。Darwin・Glibc・WinSDK は対応する OS / canImport の正の条件分岐内に限ります。同 checker は `app/MacAmbientJev/Tests` 内の XCTest import も禁止し、Linux で async `setUp` が deadlock する XCTest ではなく swift-testing（`import Testing`）を使うことを検査します。Windows の OS file API は条件付きの `CWindowsSession` target に隔離します。Foundation、Synchronization による保存・同期は Core に置かれます。録音 FLAC codec の `RecordingFLAC`、`FLACTimelineReader` と bitstream / frame decoder / MD5 実装も Core にあり、Foundation と `SessionFileAccess` を使い、Apple framework や外部 Swift package に依存しません。Encoder は bounded block 単位で書き込み、reader は CRC / MD5 を検証し bounded random-access frame index を構築します。Core に置く音声 import API は platform-neutral な `CanonicalAudioConverting` contract、mean-channel `ImportedAudioPCM.downmix`、5 秒 chunk を使う `ImportedAudioTimelineWriter` と、保存済み original から処理 timeline を構築する [`ImportedAudioTimelineBuilding`](../app/MacAmbientJev/Sources/MacAmbientJevCore/ImportedAudioTimelineBuilding.swift) protocol です。音声 decoder / SRC 実装は Core に OS import を追加せず、AppleSupport の AVFoundation converter と WindowsSupport の miniaudio converter に分離します。発話文判定では Core の `DecisionProvider` が provider の protocol です。Core は [`DecisionProviderFactory`](../app/MacAmbientJev/Sources/MacAmbientJevCore/DecisionProviderFactory.swift) / `LoadedDecisionProvider`、[`ClauseTaggerModelIdentity` / `ClauseTaggerPrediction` / `ClauseTaggerModelError`](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerPrediction.swift)、同期 [`ClauseTaggerDecisionLogic`](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerDecisionLogic.swift)、共有 [`ClauseTaggerEncoding`](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerEncoding.swift) / [`ClauseTaggerSpanProjection`](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerSpanProjection.swift)、および typed configuration と Unigram Viterbi を含む Foundation-only `ClauseTaggerTokenizer` を所有します。これらは Apple framework や外部 Swift package に依存しません。Core ML model と、それを使う `LocalClauseTagger` actor は AppleSupport にあります。**portable は「純粋関数だけ」という意味ではありません。**

Mac Runtime は Core の `ASREngine` / `DiarizationEngine` の実推論を実装し、Linux / Windows の `MacAmbientJevPortableRuntime` は Qwen3 ONNX ASR、Community-1 ONNX 話者分離、Silero VAD、`ONNXClauseTagger` ## 録音とライブ表示のデータフロー

```text
マイク / システム音声
  → TimestampedMonoSink（全入力 channel の平均）
  → AudioBlockRing
  → AudioCaptureDrain（連続 SRC → 16 kHz mono float32）
  → DurableAudioWriter → 保存済み PCM chunk / checkpoint（確定後は 16-bit FLAC へ変換）
                                              ↓
                                      LiveVADSession
                                              ↓ 閉じた VAD 区間
                                       LiveASRSession
                                              ↓ segment.created / asr.completed 等
                                       events.jsonl
                                              ↓ TranscriptMaterializer
                                        暫定のライブ表示（初期値は ASR 原文）
```

入力 callback と保存側はリングで分離します。保存処理はライブ ASR の完了を待ちません。タイムスタンプ上の欠落は gap として記録し、無音で埋めるため、保存音声と後段の時刻座標が一致します。

ライブ VAD は閉じた発話区間を渡し、連続発話は最大 14 秒で分割します。分割の端数 continuation も保持します。長い発話は区間が閉じるまで初表示が遅れます。ライブ中は話者分離を行わず、結果は暫定です。

`LiveASRSession` はセッション内で materialized 行の配列を保持します。`segment.created` の保存と ID による重複登録排除だけでは認識済み行を再構築しません。待ち件数は durable 登録済み ID 数から ASR 完了・失敗が durable になった ID 数を引き、集合差を作らずに求めます。`process` は同じ登録処理を使いますが、登録だけの中間 progress は作りません。行は `asr.completed` / `asr.failed` の保存後、または durable な発話文イベント適用時に `TranscriptMaterializer` で更新します。ASR 完了後は判定応答を待たず原文を表示し、境界 assessment が未保存・保留・失敗なら原文のままです。ライブの境界判定 run と優先度 run はライブセッションの開始時に決まり、そのセッションの active run として扱います。snapshot と completion もこの配列を使い、保存に失敗したイベントは行・件数に反映しません。オフラインの materialization とアプリのライブキュー所有はこのキャッシュとは独立です。

ライブ ASR の結果は保存直後に原文で表示し、区間の順序と結果（空・失敗を含む）を `LiveContentPrioritySession` の独立キューへ渡します。キューは次区間の保存またはテキスト列の終端を待って区間ごとに境界を判定し、成功した assessment の保存後に限り F・B除去範囲を表示へ反映します。`ClauseBoundaryAssembly` で閉じた BTSJ 発話文を保存してから最大40発話文の batch で優先度を判定し、再試行待ちでない保存済み LOW slice を表示から除きます。境界・優先度の待機や失敗は ASR drain・原文表示へ伝播しません。録音停止ではテキスト列の終端をキューに伝え、確定処理は開始時点で保存済みのライブ判定を固定してからキューを取り消します。確定・再試行の優先度再利用では、比較する各 run 自身の保存済み F・B除去範囲をその run の発話文 parts に適用して区切りなしで連結し、UTF-8 byte 列が完全一致する場合だけ再利用します。ライブの F・B除去範囲を確定側・再試行側の原文へ移しません。[ライブ](live.md)・[発話文判定](decision-engine.md)

[`LiveTranscriptionState`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/LiveTranscriptionState.swift) は Pipeline の状態保持型で、session ごとの FIFO batch、最新音声 checkpoint、failure、content-priority status、VAD の segment count / failure を保持し、ASR task や VAD session / polling task は所有しません。[`LiveTranscriptionCoordinator`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/LiveTranscriptionCoordinator.swift) は `@MainActor` で ASR task と task ID、VAD session と polling task を所有して ASR drain、thermal wait、VAD polling を実行し、録音終了も注入された [`RecordingFinishEffects`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/RecordingFinishEffects.swift) を通して調整します。capture stop 後に VAD polling を止めて VAD を finish し、正常時は `.finishLive` を enqueue します。writer failure では保存済みの正常な durable prefix を残し、ライブ状態を破棄して live transcription を cancel した後、`.finalize(sessionID: sessionID, metadataPolicy: .reject)` を enqueue します。VAD failure でもライブ状態を破棄・cancel して録音全体の finalization を enqueue します。capture stop が throw した場合は polling とライブ状態を cleanup して cancel し、処理要求を enqueue せず idle resource release を依頼します。[`RecordingFinishOutcome`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/RecordingFinishEffects.swift) が録音終了結果の typed boundary です。

録音開始の順序は Pipeline の [`RecordingStartCoordinator`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/RecordingStartCoordinator.swift) が所有します。`@MainActor` の値型で、注入された [`RecordingStartEffects`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/RecordingStartCoordinator.swift) を通して、lifecycle の `.starting` 遷移、session 作成、capture 開始、`.recording` への遷移とライブ文字起こし状態の開始、開始中に届いた capture failure の保留と処理、ライブ session 作成を順に実行します。ライブ session の作成失敗は録音を継続したまま効果へ通知します。開始が失敗した場合は、取得済み音声または破損した durable data を含む session を残して一覧更新を依頼し、空の session は削除します（削除に失敗したときは理由を失敗文言へ連結します）。取り消しは `RecordingStartFailure.cancelled`、それ以外は `.failed(message)` で効果へ渡し、lifecycle を idle に戻して idle resource release を依頼します。マイク権限の確認と UI、録音先ディレクトリの作成、マイク入力音量の設定、状態表示は効果の実装側（Mac では `AppState`）に残り、停止と終了処理の順序は従来どおり `LiveTranscriptionCoordinator` が担います。Mac の `AppState` と Windows engine の `EngineApplication` は同じ `RecordingStartCoordinator` を使います。fake effects の tests は [RecordingStartCoordinatorTests.swift](../app/MacAmbientJev/Tests/MacAmbientJevPipelineTests/RecordingStartCoordinatorTests.swift) にあり、Mac 側の開始失敗は [RecordingFailureTests.swift](../app/MacAmbientJev/Tests/MacAmbientJevAppTests/RecordingFailureTests.swift) が `AppState` 経由で確認します。

[`SessionProcessingCoordinator`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/SessionProcessingCoordinator.swift) は `@MainActor` で処理 queue の dequeue・hold / resume・begin・run・pause と drain を行います。また `recoverPendingSessions` が storage-maintenance gate、注入された scan と maintenance を調整し、現在の録音、maintenance failure、すでに pending の session を除外して回復要求を enqueue / drain します。起動時は公開済み deferred decision retry を自動 enqueue せず、未公開の interrupted decision run は recovery request に変換します。`retryDeferredDecisions` は利用者の明示操作で保留中の判定を再試行し、interrupted run と利用者 retry の双方で単一の `decisionRetryRequest` 変換を共有します。明示 retry と interrupted decision run の recovery は、現在の公開済み snapshot に対する新しい decision retry request を一度だけ実行し、最初の推論失敗で fail fast します。失敗した retry は途中結果を破棄し、公開済みの active snapshot と metadata を変更しません。途中まで成功した判定結果を partial-failure update として公開しません。推論失敗後、coordinator は failed-run cleanup を始める前に cancellation を一度確認します。その時点ですでに取り消されており、まだ durable outcome がなく cleanup も始まっていない場合だけ paused / held とし、`cancelled` warning `処理は中断されました。次回の起動時に再開できます` を表示します。この場合 `processing_failure`、Windows の `state.failures` failure entry、failed run end は作りません。cleanup を始めた後は coordinator / writer が cancellation を再確認せず、その retry が開始した各 run の `processing.run.completed` (`succeeded: false`) の保存をすべて試みます。durable な failed completion は late cancellation / shutdown に優先し、retry は typed `.failed` を返して held / cancelled にはなりません。完了記録の実 I/O failure も処理 failure とし、元の推論 error と保存 error の両方を含めますが、これを durable completion とはみなしません。保存できなかった run は unfinished のまま起動時 recovery 対象になります。失敗完了が durable に保存された run は起動時に再 enqueue せず、再試行は利用者が明示します。成功 retry は decision snapshot の metadata publication が durable success で、publication 後の cancellation、モデル / settings の未準備、または shutdown で paused / held に戻したり自動 rerun したりしません。`succeeded: true` の run end だけがあり metadata publication に至らなければ durable success ではなく、起動時 recovery が適用されます。retry は typed `SessionProcessingResult` を返し、`.failed` を coordinator の `finished` 結果まで伝播します。成功した retry も自動 export はしません。この outcome ordering の変更は decision retry branch に限り、finalization と他の処理の pause / failure / recovery semantics は変えません。[`SessionRecoveryEvent` と `SessionRecoveryStatusSnapshot`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/SessionRecoveryEffects.swift) は復旧状態を App へ渡す typed boundary です。`SessionProcessingExecuting` / `LiveTranscriptionExecuting` は処理 engine の境界、各 Effects protocol は App 側の効果境界で、Pipeline tests は fake executor / effects を使います。再処理 claim は AppState が enqueue 前に `SessionProcessingQueue` で行い、coordinator が処理後に release します。

[`AppState`](../app/MacAmbientJev/Sources/MacAmbientJev/AppState.swift) は coordinator と executor、session scanner / maintenance の依存を組み立て、capture の開始・停止などの OS capture 操作を効果として提供し、typed outcome / event を画面 status や transcript 表示へ反映します。start・finish・recovery の順序制御や要求の filter は Pipeline が担います。`RecordingLifecycle` / `SessionProcessingQueue` / `SavedSessionOperations` は `@Published` 値として公開され、キューと再処理 claim の状態は保存済み録音一覧へ反映されます。NSOpenPanel / NSWorkspace は App に置きます。ライブ文字起こしの view と view model は App target の [`LiveTranscriptView`](../app/MacAmbientJev/Sources/MacAmbientJev/LiveTranscriptView.swift) と [`LiveTranscriptViewModel`](../app/MacAmbientJev/Sources/MacAmbientJev/LiveTranscriptViewModel.swift) にあります。portable な fake tests は [RecordingFinishCoordinatorTests.swift](../app/MacAmbientJev/Tests/MacAmbientJevPipelineTests/RecordingFinishCoordinatorTests.swift) と [SessionRecoveryCoordinatorTests.swift](../app/MacAmbientJev/Tests/MacAmbientJevPipelineTests/SessionRecoveryCoordinatorTests.swift) にあり、App target の [LaunchDecisionRecoveryTests.swift](../app/MacAmbientJev/Tests/MacAmbientJevAppTests/LaunchDecisionRecoveryTests.swift) と [LaunchMaintenanceStatusTests.swift](../app/MacAmbientJev/Tests/MacAmbientJevAppTests/LaunchMaintenanceStatusTests.swift) は起動時の状態表示 integration を確認します。

## ファイル入力と共通確定処理

ファイル入力では Core の [`AudioImporter`](../app/MacAmbientJev/Sources/MacAmbientJevCore/AudioImporter.swift) が original を session の audio directory に無再圧縮で一度コピーします。Core の [`ImportedAudioTimelineBuilding`](../app/MacAmbientJev/Sources/MacAmbientJevCore/ImportedAudioTimelineBuilding.swift) は `build(from:into:sessionURL:) async throws -> AudioCheckpoint` を定義し、既に保存された original をコピーせずに processing timeline を作ります。Mac の AppleSupport [`AudioFileTimelineBuilder`](../app/MacAmbientJev/Sources/MacAmbientJevAppleSupport/AudioFileTimelineBuilder.swift) は bounded buffer で decode し、全 channel の平均後に連続 SRC して 16 kHz mono float32 の timeline を保存します。Mac app は AppleSupport の builder を使い、ProcessRecording CLI は compile-time platform composition で Mac の AppleSupport builder または portable の [`PortableImportedAudioTimelineBuilder`](../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/PortableImportedAudioTimelineBuilder.swift) を選んで [`SessionProcessingAudio`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/SessionProcessingAudio.swift) に注入します。WindowsSupport の [`AudioFileTimelineBuilder`](../app/MacAmbientJev/Sources/MacAmbientJevWindowsSupport/AudioFileTimelineBuilder.swift) も同 protocol に準拠し、PortableRuntime の [`PortableImportedAudioTimelineBuilder`](../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/PortableImportedAudioTimelineBuilder.swift) は Windows ではこの builder に委譲します。Linux は miniaudio 0.11.23 で WAV / FLAC / MP3 を読み、既に16 kHz mono の入力だけを受け付け、それ以外はエラーにします。public [`PortableAudioFileImporter.open(inputURL:sessionURL:)`](../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/PortableAudioFileImporter.swift) は `AudioImporter` で original を一度コピーし、`SessionLayout.processingDirectory`（session 内の audio 配下にある processing directory）へ timeline を作ります。TranscribeFile はこの importer を使い、実行ファイル内に decoder を実装していません。original の bytes は保持します。録音・import の VAD、ASR、話者分離は canonical 入力を直接消費し、処理段階で SRC や downmix は行いません。

録音停止、ライブ失敗後の保存音声、import、利用者による再処理、クラッシュ復旧、ProcessRecording CLI の import / resume は、`NativeSessionProcessor` の共通確定処理を使います。TranscribeFile は別の評価経路で、[`FileTranscriptionPipeline`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/FileTranscriptionPipeline.swift) による VAD / ASR 結果と評価 artifact を作り、session の全段階確定処理は行いません。

[`SessionFileProcessingService`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/SessionFileProcessingService.swift) は Pipeline の typed `ImportRequest` / `ResumeRequest` / `Inspection` API で import・inspect・resume、recovery rescan と action routing、処理結果の検証・export を所有します。`SessionFileProcessingResources` は engines / `ContentPriorityAccess` / optional `DecisionProviderFactory` を束ねます。CLI の import は入力と保存先を検証し、必要な processing resources と decision preflight を session 作成前に解決してから、Pipeline の [`RetainedSessionImporter`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/RetainedSessionImporter.swift) で一時 session を作ります。`RetainedSessionImporter.importRetainedSession(audioURL:)` は `SessionBootstrapper` で session を作り、Core `AudioImporter` で原音声を一度コピーし、session 識別子・URL・単一の `SessionFinalizeRequest`（metadata policy は `.reject`）を持つ `RetainedSession` を返します。処理も JSON 出力もせず、失敗時は作成済み session を持つ `RetainedImportError` を投げて削除か保持かを呼び出し側に任せます。この finalize request を確定できるのは一か所だけで、Mac app は `SessionProcessingCoordinator.enqueue` に渡し、CLI は注入された timeline builder と `NativeSessionProcessor` で await して確定します。`--keep-session` がなければ CLI が作成した一時 session は完了・失敗・一時停止のいずれでも cleanup 対象で、Mac app の import は session を保持します。保存 root は `ValidatedSessionPaths` で区別します。CLI の外部 root は `externalRoot(_:protectedRoots:)` で protected root 検査を受け、アプリ自身の root だけが `trustedApplication(_:)` で検査なしに admit されます。inspect・resume・coordinator の launch recovery と decision retry の action 振り分けは、`RecoverableProcessingAction` から作る [`SessionRecoveryPlan`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/SessionRecoveryPlan.swift) が共有し、inspect 名・推論要否・enqueue する request を一か所で決めます。

resume は出力先 containment と session lookup の後、最初に read-only recovery inspection を行います。その action が推論を要する場合だけ resources を作成・preflight し、decision inference が指定された場合は decision provider preflight も maintenance より前に行います。続いて必要な storage maintenance を行い、session を再走査して最新 action を dispatch します。decision-only recovery を判定無効のまま resume した場合は resources や inference を使わず、公開済み local transcript を export します。inspect と推論不要の export-only resume は model resources を作らず、model environment も読みません。要求された decision mode を満たす completed session の export も inference event を追加しません。decision retry が失敗した場合は typed failure の正確な `発話文の判定を再試行できませんでした: <reason>` を返し、collector state / export validation の一般的な failure に置き換えず、export しません。推論失敗でもすでに公開済みの metadata は保持します。

CLI の [platform composition](../app/MacAmbientJev/Sources/MacAmbientJevProcessRecording/main.swift) は compile-time で分岐します。Mac は `SessionProcessingEngines.production(paths:)` と AppleSupport の timeline builder を使い、decision inference が必要な操作で `--with-decisions` が指定された場合だけ `MAC_AMBIENT_JEV_CLAUSE_TAGGER_MODEL_DIRECTORY` を読みます。この既存の絶対 directory は ClauseTagger.mlpackage と tokenizer.json を含み、`LocalClauseTagger` に明示注入されます。これは app bundle の tagger とは別の directory で、Mac ProcessRecording は他の model-path environment variables を読みません。Linux / Windows は [`PortableProcessingConfiguration.resolve`](../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/PortableProcessingConfiguration.swift) と [`PortableSessionEngineBundle(configuration:)`](../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/PortableSessionEngineBundle.swift) を使います。推論が必要な操作では `MAC_AMBIENT_JEV_SILERO_MODEL`、`QWEN3_ASR_ONNX_MODEL_DIRECTORY` / `QWEN3_ASR_ONNX_MODEL_SIZE`、`MAC_AMBIENT_JEV_DIARIZATION_ONNX_MODEL_DIRECTORY` を解決し、`MAC_AMBIENT_JEV_CLAUSE_TAGGER_MODEL_DIRECTORY` は `--with-decisions` 時だけ読みます。ASR・diarization・tagger の ONNX session は指定 thread 数、VAD は1 thread です。portable decision identity は backend `onnx-clause-tagger` と pinned model identity を記録します。

Portable の import / resume は export-only resume も含め `--threads N` が必須で、`N` は `1...min(4, logicalCPUCount)` です。Mac は `--threads` を拒否します。inspect は両 platform で `--with-decisions` と `--threads` を拒否します。`--run-id`、`--metrics-output`、`--thermal-output`、`--memory-output` は Mac の import / resume に限り四つ全て必要です。これらを含む measurement option は portable parser が filesystem side effect より前に拒否します。[`RunMonitor`](../app/MacAmbientJev/Sources/MacAmbientJevProcessRecording/RunMonitor.swift) は macOS 限定です。Mac ProcessRecording は推論 resource を作成する import / resume の開始時に thermal check を行い、critical 時に処理を pause し、measured run では thermal / memory sample を記録します。portable CLI は monitor を起動せず熱状態で pause せず、`--low-heat` は pacing のみを変えます。

完了 disposition は collector が受け取った `ProcessingState.complete` を満たす必要があります。export は全 session から materialize した recognized text を持つ `MaterializedTranscriptSegment` 配列を pretty-printed / sorted-key JSON にし、segment schema や全行配列の形式を変えず、別形式の envelope にもしません。`--with-decisions` を指定し、認識済み本文がある場合は active clause-boundary / content-priority run、空の boundary / priority retry targets、空の `pendingDecisionTargets` を成功条件とします。判定 preflight が import session 作成前に失敗した場合は session も local transcript もありません。必須ローカル結果が公開された後に判定 request が失敗した場合は公開済み結果を保持し、pending targets を残しますが export を行わず CLI は failure になります。認識結果がない場合は decision run を要求せず空配列を出力します。

```text
保存音声
  → 新しい VAD run
  → offline diarization（保存タイムラインから CAF を生成）
  → VAD 区間を保持した ASR
  → 必須のローカル3段階の保存済み結果を検証・公開
  → platform-local decision provider による境界判定（任意）
  → BTSJ 発話文の組み立て
  → platform-local decision provider による優先度判定（任意）
  → 判定 run・保留一覧を一括公開
```

確定処理の必須ローカル段階は segmentation・diarization・ASR です。任意の境界・優先度判定は Mac の Core ML provider または PortableRuntime の ONNX provider を使います。CLI は `--with-decisions` を指定した場合に provider を組み立て、指定なしでは `.disabled` のままです。decision model preflight は import session の作成前に行われるため、そこで失敗した場合は session や local transcript が作られたとは限りません。必須ローカル結果の公開後に decision request が失敗した場合は、その結果を保持して判定を保留し、decision export は失敗します。import では `--keep-session` がない一時 session は失敗後も cleanup 対象です。

区間は保存タイムラインの frame index による半開区間です。ASR には VAD 区間を細分化せず渡し、話者の詳細 span は保持します。複数話者を含む行の見出しは 80% ルールで決めます。FluidAudio adapter だけは実音声内から最終モデル window の padding 内へ延びる終端を EOF に合わせます（[終端の規則](final.md)）。EOF 以降の開始、padding を超える終端は adapter で明示エラーにし、確定パイプラインでも全 span の実音声範囲を厳密に検証します。

確定処理開始時に `finalization_attempt` を running として保存し、処理中のイベントは既存ログへ追記します。必須ローカル段階が成功するまでは公開済み `active_runs` を変更しません。ローカル段階の公開と判定結果の公開は、それぞれ一回の metadata write で行います。判定 snapshot の保存に失敗しても公開済みのローカル結果を保持します。失敗・熱による一時停止では直前の正常な結果を維持し、再開は新しい確定 run の全量実行です。原音声は後段の失敗で削除しません。セッションの source 情報を読み取れる場合、`NativeSessionProcessor` は確定処理中に作った一時音声を完了・失敗・一時停止、およびその他の開始失敗で削除します。manifest の読み取り失敗などで source を特定できない開始失敗では cleanup を約束しません。cleanup の失敗は報告し、ファイルシステムエラー時の削除完了は保証しません。import original と audio storage metadata は保持します。

## 発話文判定

境界と優先度の単位は BTSJ 発話文です。接続表現で節が完結しても続く場合や倒置・後置・付け足しが続く場合は同じ発話文として扱い、フィラーや言い直しだけでは境界にしません。モデルの `span_probs` を O=0 / F=1 / D=2 / B=3 の argmax（同率は最小 index）で分類し、F・B を除去して O/D は保持します。Swift Character は構成する全 scalar が F または B の場合だけ除去し、F と B の混在も除去します。一つでも O または D の scalar があれば Character 全体を保持し、隣接する除去 Character は一つの範囲にまとめます。詳細は [発話文判定](decision-engine.md) を参照してください。形態素解析、辞書、規則による別分割・判定は行いません。ASR・話者分離・発話文判定はすべてローカル処理で、判定テキストをネットワークへ送りません。フィラー・相槌除去後に本文がある認識済み行は表示・書き出しの対象です。

Mac アプリの判定モデルは [Pokojaka/modernbert-ja-30m-utterance-tagger](https://huggingface.co/Pokojaka/modernbert-ja-30m-utterance-tagger) の commit `5c0213592cf8d59fc0b665183ab7536ddde05d1f` から取得します。app code は MIT license、同梱する学習済みモデルは名大会話コーパスで学習した CC BY-NC-ND 4.0 で、[Hugging Face model repository](https://huggingface.co/Pokojaka/modernbert-ja-30m-utterance-tagger) に掲載されています。[`clause_tagger_model.json`](../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/Resources/clause_tagger_model.json) が取得元と全形式の共有 manifest で、各ファイルの repository 相対 path、byte count、SHA-256 を pin します。`scripts/build_app.sh` は `python3 scripts/fetch_clause_tagger.py --format coreml` を実行し、検証済みの ClauseTagger.mlpackage、tokenizer.json、LICENSE.md を app bundle の Resources/clause-tagger に入れます。アプリはその固定位置から読み込み、実行時の download や path override はありません。Core ML は CPU only・float32 で推論し、tokenizer / configuration / Unigram Viterbi は Foundation-only の Core 実装です。PortableRuntime は同じ manifest の pins を使い、明示的な `python3 scripts/fetch_clause_tagger.py --format onnx` で `.build/clause-tagger-onnx/<commit>/clause-tagger-onnx` に取得した directory の5つのファイル（ClauseTagger.onnx、tokenizer.json、export.json、LICENSE.txt、LICENSE.md）を byte count と SHA-256 で検証して、ONNX Runtime CPU 上の [`ONNXClauseTagger`](../app/MacAmbientJev/Sources/MacAmbientJevPortableRuntime/ONNXClauseTagger.swift) を使います。portable backend identity は `onnx-clause-tagger` で、model ID / revision / tokenizer hash を provenance に記録します。具体的な形状・入出力、tokenizer 検証、符号化と履歴要件は [発話文判定](decision-engine.md) を参照してください。

`ContentPriorityAccess` はアプリと CLI が使う共有 access enum です。アプリの [`AppState`](../app/MacAmbientJev/Sources/MacAmbientJev/AppState.swift) は同期の `loadProvider` closure で `LocalClauseTagger` actor を作成し、provider と `ClauseTaggerModelIdentity` を `LoadedDecisionProvider` として返します。Core の汎用 `DecisionProviderFactory` は注入された同期 `@Sendable () throws -> LoadedDecisionProvider` closure を使い、同時要求の load を一つに集約して lock の外で実行し、その成功または失敗を factory のプロセススコープの寿命中 cache します。throw された CancellationError も同じ失敗として cache され、再試行・reset はありません。同時要求は同じ load 結果を共有します。`makeCoordinator()` はその provider と identity を使い、`localModelIdentity()` は同じ cache から identity を返すだけで判定 request・利用回数・token を発生させません。アプリは `factory.makeCoordinator()` を呼ぶ closure を `.localTagger(..., usageCounter:)` に渡します。設定画面は [`ClauseTaggerModelIdentity`](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerPrediction.swift) を Core から直接参照します。ProcessRecording CLI は既定で `.disabled` を渡し、`--with-decisions` のときだけ platform-local provider を構成します。システム音声キャプチャ CLI とライブ遅延計測 CLI も `.disabled` で任意判定を省略し、tagger をロードしません。

Core の `DecisionProvider` が判定の境界で、Core ML / ONNX tagger とテスト用 provider が同じ要求・応答型を使います。`DecisionCoordinator` と共有 `DecisionUsageCounter` は provider 呼出し一回ごとに1 request として計数し、モデルが読んだ入力 token を記録します。境界の一 request は候補と全 source token を網羅する source-only 窓、および後続区間があれば任意の継続入力を含みます。窓の数によらず一 request と数え、全窓と継続入力の token 数を合計します。優先度判定は最大40 sequence の一 batch 呼出しを一 request とし、実入力 ID 数を合計します。

境界要求は raw ASR text を入力にします。本文のある終端区間は候補がなくても F・B除去範囲を判定する source-only 推論を実行し、成功時は実際の request と `clause_boundaries.assessed.filler_ranges` を保存します。保存 key `filler_ranges` の値は `{start,end}` の配列で、raw ASR text の UTF-16 半開範囲によりフィラー・相槌除去範囲を表します。優先度要求はフィラー・相槌除去後本文の最大40件です。設定の「モデルを確認」は cache した tagger の identity を表示するだけで、判定 request・利用回数・token を発生させません。

ASR 原文とイベントは変更しません。保存済み境界 assessment の F・B除去範囲だけを原文の raw UTF-16 座標へ適用し、materialization は保存済み範囲と再試行待ちでない保存済み LOW slice を表示本文へ投影するだけで、辞書もモデルも使いません。画面、コピー、accessibility、文字起こし txt、CLI JSON の `display_text` は共通の表示本文を使います。ProcessRecording CLI で判定を無効にした場合は assessment や F・B除去範囲を作らず、`display_text` に原文を出します。

開始 run の provenance は engine、model、version と設定を保存します。run には実際にロードした model ID と state hash revision を記録し、成功した各 request record には request ID と入力 token 数を保存します。request を処理したモデルはその run の provenance が示します。共通の `DecisionProvider`、型、portable encoding と F・B除去範囲 projection は [ClauseTypes.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTypes.swift)、[ClauseTaggerPrediction.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerPrediction.swift)、[ClauseTaggerEncoding.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerEncoding.swift)、[ClauseTaggerSpanProjection.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerSpanProjection.swift)、[`ClauseTaggerDecisionLogic.swift`](../app/MacAmbientJev/Sources/MacAmbientJevCore/ClauseTaggerDecisionLogic.swift)、materialization は [Materialization.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/Materialization.swift) と [TranscriptTextProjection.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/TranscriptTextProjection.swift)、factory は [DecisionProviderFactory.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/DecisionProviderFactory.swift)、Core ML model と `LocalClauseTagger` actor は [ClauseTaggerModel.swift](../app/MacAmbientJev/Sources/MacAmbientJevAppleSupport/ClauseTaggerModel.swift) と [LocalClauseTagger.swift](../app/MacAmbientJev/Sources/MacAmbientJevAppleSupport/LocalClauseTagger.swift)、provenance と計数は [DecisionEnrichmentCoordinator.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/DecisionEnrichmentCoordinator.swift) と [DecisionUsageCounter.swift](../app/MacAmbientJev/Sources/MacAmbientJevCore/DecisionUsageCounter.swift) を参照してください。

## 待機中のモデル解放

App は録音・ライブ認識・確定処理の待ち行列・発熱による保留・実行中の確定処理がすべてなくなった時点で `NativeSessionProcessor.releaseIdleResources()` を呼び、Qwen3-ASR と話者分離のモデルを解放し、MLX のバッファキャッシュを空にします。この解放は Core ML 発話文 tagger を対象にしません。正常にロードした tagger は provider factory の寿命中 cache され、idle release 後も保持されます。ASR model 状態は「録音開始時に準備します」に戻ります。解放中に始まったモデル準備・ライブ認識・確定処理は解放の完了を待ちます。次の録音や確定処理では ASR と話者分離を読み込み直すため、録音開始直後のライブ表示は読み込みの数秒だけ遅れます。CLI の import / finalize / decision-retry は [`SessionFileProcessingService`](../app/MacAmbientJev/Sources/MacAmbientJevPipeline/SessionFileProcessingService.swift) が各 processor-backed operation の完了・非 completed 結果・throw 後に `processor.releaseIdleResources()` を await します。decision provider factory を含む resources は操作スコープで、inspect と export-only resume は resources / processor を作りません。
